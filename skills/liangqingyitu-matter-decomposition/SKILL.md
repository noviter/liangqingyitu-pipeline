# 三定方案业务拆解与清单整理

## 业务基线和阶段边界

本 Skill 以《处室板块视角两清一图梳理》中的 Prompt1“**三定方案业务拆解与分类**”和 Prompt2“**阶段成果 Excel 整理**”为唯一业务规则来源。只做输入路径、输出目录、处室名称、文件名和纳入/排除范围的参数化，以及 Excel 读取、生成、保存和校验。

本 Skill 只执行阶段 1。生成 `人工核验前` 文件后必须停止。业务人员另存的 `核验后` 文件才是阶段 2 唯一正式输入；不得用初稿、旧版本或自动规则覆盖人工修改。人工样例仅可用于核对列名、列序、合并、黑白灰样式、边框、换行、列宽和行高，绝不能读取或复用其事项、分类或其他业务答案。

## 输入参数

- 职责 Excel 路径：只读取**第一个工作表**。不得读取该工作簿的其他工作表。
- 输出目录与文件名。
- 处室名称：优先从第一个工作表的单位、部门/处室字段提取；若传入参数与原表不一致，停止并列入待确认说明。
- 明确的纳入/排除范围：没有明确排除时，保留全部职责，包括“领导交办的其他事项”。

读取首个工作表中的单位、处室和“处室职能”原文。保留带条款序号的完整职责原文，并按原职责顺序处理。

## 拆解和分类规则

- 先识别完整复合动词，再拆并列动作和不同业务对象。必须保留“参与拟订”“承担指导”“辅助做好”“负责指导”等完整责任状态，不能把参与、协助或事务性支撑改写为主办权责。
- 每条事项保留完整动词前缀、业务对象和原文中的责任范围限定；并列事项拆开后应能独立读通。
- 固定政务名词（如法律法规、方针政策）及完整业务动作闭环（如调查处理、监督管理）不得机械拆词。
- 不合并相同动作，不去重，不打乱原文及同一职责内的顺序，不增加原文没有的职责、权限或办理步骤。
- 职能类型只能为“督导、组织、负责、参与”之一。先判断复合动词：组织实施/组织开展为负责；组织协调/统筹协调为组织；监督实施/监督执行、负责指导、承担督导/监督为督导；参与拟订/参与编制为参与；提出意见/建议为参与，提出目标/规划为负责。无法由复合动词判定时，再按核心动作映射：指导、检查、监督、督促、考核、备案、督导、督察为督导；组织、统筹、牵头、召集、推进为组织；承担、承办、负责、实施、执行、拟订、编制、起草、制定、管理、建设、审批、贯彻落实为负责；参与、协助、辅助、配合、提出意见/建议为参与。
- 无法确定拆解边界、来源职责对应关系或职能类型时，不得猜测补齐。该问题不写入正式四列表，改写入单独的、面向业务人员的待确认说明，并说明缺少的原文边界或分类依据。

## 正式输出与版本保存

阶段 1 正式审核文件为 `01_处室名称_三定方案业务事项清单_人工核验前.xlsx`，仅保留一个业务清单工作表和四列：

| 列 | 字段 | 要求 |
|---|---|---|
| A | 处室名称 | 来源处室名称。 |
| B | 职责 | 带条款序号的完整职责原文，不概括、不改写。 |
| C | 事项 | 原子化事项，不附加分类标签。 |
| D | 职能类型 | 督导、组织、负责、参与之一。 |

不得增加事项 ID、置信度、模型说明、证据 ID、JSON、隐藏工作表、附加技术列或技术交付物。程序内部临时结构如有需要，必须留在交付目录和工作簿之外，不作为业务人员审核成果。

同时输出：

- `输入资料清单.xlsx`：仅列职责文件、首个工作表、处室名称、职责数量、运行日期和适用范围。
- `阶段1待确认说明.xlsx`：仅列无法确定的事项、分类或拆解问题及原因；没有问题时保留空的业务表头，不制造问题或答案。
- `阶段1运行说明.md`：记录本阶段的输入范围、职责数、事项数、待确认数、输出位置和“等待人工审核”的停止状态。

人工审核后，业务人员将四列文件另存为 `01_处室名称_三定方案业务事项清单_核验后.xlsx`。该文件不可被自动初稿覆盖。

## Excel 排版与交付前校验

- 首行表头为 A-D；A 列按同一处室的连续事项纵向合并；B 列按同一来源职责的连续事项纵向合并；单条事项不合并 B；C/D 永不合并。
- 使用黑白灰：黑色文字、灰色表头、正文按职责分组交替白色和浅灰色。表头加粗居中；A/D 居中；B/C 左对齐；全部单元格垂直居中、自动换行、边框清晰、列宽和行高足以显示内容，冻结首行。
- 校验仅访问首个工作表；每条事项均回溯到完整职责原文；职责与事项顺序未改变；D 列无空值且值合法；A/B 合并范围正确；C/D 无合并；正式表仅有四列；不存在人工样例业务内容；输出工作簿可正常打开。
- 校验完成后停止，等待人工审核确认；不得自动进入阶段 2 或阶段 3。
